# code-hygiene

Agent-written code carries a signature: comments that narrate the line below them, section banners in a 40-line file, reassurance about how robust the implementation is, changelog notes git already owns. Reviewers learn to skip comments entirely once most of them are noise, and the useful ones die with the useless ones. This skill removes the noise and protects the signal.

Two verbs:

- `check` - report only. A table of what would change, no edits.
- `clean` - apply the edits, commit by concern, verify.

Default to `check` when the user's ask is ambiguous or the scope is large.

## Scope first: this is a diff pass, not a repo sweep

Sweeping a whole repo produces an unreviewable diff and rewrites code nobody asked about. Unless the user names a wider target, the scope is the current change:

```bash
BASE="${1:-origin/develop}"                      # or origin/main - read the repo's AGENTS.md/CLAUDE.md
git fetch -q origin
git diff --name-only "$(git merge-base HEAD "$BASE")"...HEAD
# uncommitted work too:
git status --porcelain | awk '{print $2}'
```

Widen only on an explicit ask ("the whole `src/device-types/` tree", "every file I touched this week"). Say what scope you used in the report.

Never touch: `dist/`, `build/`, `node_modules/`, `vendor/`, `*.generated.*`, `*.min.*`, lockfiles, snapshots, migrations that have already run, or anything with a "generated by" header.

## The tells (delete these)

1. **Narration** - the comment restates the line below it. `// increment the counter` over `count++`; `// Loop through users` over `for (const user of users)`.
2. **Changelog / diary** - `// NEW:`, `// Added in v2`, `// Updated to handle the null case`, `// Previously this used fetch`, `// as requested`, `// per review feedback`. Git owns history; the PR owns the rationale.
3. **Section banners** - `// ===== HELPERS =====`, `// ---------- Main ----------`, `/* ---- types ---- */` in a file short enough to read. (A genuine table-of-contents header in a 2000-line legacy file is not this.)
4. **Signature echo** - JSDoc/docstrings that restate types. `@param userId The user id`, `@returns the result`, `"""Gets the name."""` over `get_name()`.
5. **Teaching** - explaining the language, not the code. "This is an async function that returns a Promise", "useEffect runs after render", "map creates a new array".
6. **Reassurance and self-congratulation** - "robust, production-ready implementation", "elegantly handles all edge cases", "optimized for maximum performance", "Best practice:", "cleanly separates concerns".
7. **Apology and hedge** - "Note: this is a simplified version", "In a real implementation you would...", "This should probably be refactored", a bare `TODO` with no ticket and no owner.
8. **Emoji and fancy Unicode** in comments, log strings, and identifiers - em dash, en dash, arrows, checkmarks, ellipsis character, `>=`/`<=` glyphs. ASCII only. (Leave user-facing UI copy alone unless the repo's style rule covers it.)
9. **Placeholder residue** - `// Your code here`, `foo`/`bar`/`baz` names that shipped, `example.com` in a real config, `console.log('here')`, `print(x)`, `debugger`, `.only(` on a test, a `describe.skip` with no reason.
10. **Dead code kept just in case** - commented-out blocks, unused imports, unreferenced exports, a flag nothing reads.
11. **Defensive cruft with no caller** - a `try/catch` that catches, logs, and rethrows unchanged; `if (!x) return` for a value the type system already guarantees; `?? ''` on a non-nullable field. Requires tracing callers before you touch it (see the safety rule below).
12. **Third implementation of the same helper** - another date formatter, another `slugify`, another `sleep`. Point at the existing one.
13. **Single-use wrapper** - a class or module with one method called from one place, wrapping one call.

## What survives (the part that takes judgment)

A comment earns its place when it says something the code cannot:

- **The nonobvious why.** "BSN rate-limits at 360 session calls/hr, so we batch" - a reader cannot derive that from the code.
- **An invariant or contract** that isn't checkable at the call site: "callers must hold the lock", "must stay in sync with the manifest schema version".
- **A link to a ticket, spec, RFC, or upstream bug** that explains a workaround. This is the single most valuable comment type; never delete one.
- **A footgun warning.** "Do not reorder - the swap has to be atomic or a half-written card boots."
- **Magic numbers, regexes, bit math, protocol offsets, wire formats.** Anything where the value came from a document.
- **Public API doc comments** that a consumer reads through tooling (hover, generated docs).
- **Lint pragmas with a reason** - `eslint-disable-next-line <rule> -- <why>`, `@ts-expect-error <why>`, `# noqa: E501 <why>`. Delete the pragma only if the underlying issue is gone.
- **License headers, generated-file markers, codeowner hints.**

The test: **delete the comment and ask what was lost.** If the answer is "nothing, the code says that", it goes. If a reader would still ask "why is it like this", it stays. If a reader would ask "what does this do", the fix is a better name, not a comment - rename, then delete.

When you cannot tell, keep it and list it under "left for a human". A wrongly deleted why-comment is worse than ten surviving narration comments.

## Procedure

1. **Scope** - resolve the file list per the section above. Print it.
2. **Grep the loud tells** - cheap and high-yield. `scripts/find-slop.sh <files...>` in this skill directory, or the greps inline below. This produces candidates, not verdicts.
3. **Read every hit in its surrounding code.** No exceptions. A `// NEW:` may sit above the one line that explains a protocol quirk.
4. **Classify** each candidate keep / kill / rename-instead / human.
5. **Apply, one concern per commit.** Comment removal, dead-code removal, and renames are three different commits and three different risk levels. A reviewer should be able to approve the comment commit at a glance.
   - `chore: drop narration comments in <area>`
   - `chore: remove dead code and unused imports in <area>`
   - `refactor: rename <x> to <y> so the comment isn't needed`
6. **Verify.** Lint, typecheck, tests. Use whatever the repo actually runs (check `package.json` scripts, `Makefile`, `AGENTS.md`/`CLAUDE.md`).
   - The comment-only commit must be a **no-op to the test suite and to the build output.** If something breaks, you deleted code, not a comment - revert that hunk.
   - For a comment-only commit you can prove it: strip comments from before/after and diff, or just confirm the test suite is untouched and lint is clean.
7. **Report** (see format below).

## Safety rules

- **Never bulk-delete with sed, a regex, or a codemod.** Every deletion is read in context. This is the whole job.
- **A character substitution is not automatically safe.** Transliterating a glyph (em dash to hyphen, ellipsis to three dots) reads as harmless and is not, in three places:
  - **Inside a regex literal.** `/…$/` became `/...$/`, which is three wildcards, so the assertion passed for any three characters and silently stopped checking anything. Escape or skip regex literals entirely.
  - **In a value, not a message.** An API response field, a DB value, a wire sentinel, a cache key, an enum. `fleet_key_hash_preview: '<hash>…'` is data the admin UI renders and a consumer could match on; changing it is a behavior change however cosmetic it looks. Convert messages (logs, errors, test names), not values.
  - **Across a value and its test at once.** The sweep changed the emitter, the fixtures AND the assertion together, so they stayed consistent with each other while all three drifted from what shipped. **A green suite proves nothing when the pass edited both sides.** Diff the values against the base branch, not just against the tests.
- **"Every changed line is a pure transliteration" is a weaker guarantee than it sounds.** It proves no line was mangled. It does not prove the line should have changed at all. Classify each changed line by what it IS (comment / message / value / pattern) before trusting a mechanical check.
- **Never delete comment prose mechanically, no matter how careful the guard looks.** A paragraph-level trimmer (whole paragraphs only, never half a sentence) with an allowlist protecting doc paths, tickets, `MUST`/`NEVER`, ENV VARs, incident notes and usage synopses still silently dropped a `PRIME DIRECTIVE: never affect the content path` invariant, a cross-file wire-shape contract, and a `TEST SEAM` note. It reported **zero** protected markers lost and passed every suite. "Is this load-bearing" is semantic; no keyword list decides it.
- **A guard you wrote can only find what you already thought of.** Auditing a change against the same allowlist that produced it is circular. Validate against an independent signal - the base branch, another tool, a reviewer - and test the guard against known positives AND negatives first, because a silent over-match looks conservative and a silent under-match looks thorough. (`re.X` strips literal spaces: `Do not` compiles as `Donot`.)
- **Reducing volume is relocation, not deletion.** Ask where the content should live before asking whether it should die. In order of preference: a long CLI-script header is usually undocumented `--help` (extract to `usage()`, nothing lost, and it becomes reachable); a header restating a doc it already cites trims to the invariant plus the link; only then compress prose by hand. Interface documentation - a JSDoc `@param` block, a sourced shell library's `Usage:`/`Inputs:`/`Outputs:` contract - is exempt from any ceiling, because it has nowhere else to live.
- **Behavior does not change.** Category 11 (defensive cruft) and 10 (dead code) are the only ones that can break something. Before removing a guard or an export, trace the callers (`rg -n '\bsymbolName\b'`, LSP references, `knip`). Not sure it is dead? Leave it, list it.
- **Don't reformat.** Keep the diff to the tells. If the repo has a formatter, run it as its own commit or not at all.
- **Don't widen scope mid-pass.** Files that catch your eye outside the scope go in the report, not the diff.
- **Respect the repo's rules.** Read its `AGENTS.md` / `CLAUDE.md` first; some repos require a comment style this skill would otherwise strip, and the base branch is repo-specific.
- **Test files count** - they collect the most narration - but a comment explaining *why a test exists* or what regression it pins is a keep.

## Grep pack

`scripts/find-slop.sh` runs all of these over the scoped files. Manually, with ripgrep:

```bash
# changelog / diary / process comments
rg -n --pcre2 '^\s*(//|#|\*|--)\s*(NEW|UPDATED|CHANGED|FIXED|ADDED|REMOVED)\b|(as requested|per (the )?(review|feedback|request)|previously (this|we)|used to be|no longer needed|for now)' -i

# reassurance / teaching / apology
rg -n -i '(production[- ]ready|robust|elegant|seamless|blazing|best practice|note that this is|simplified version|in a real (implementation|app|world)|for demonstration|this (is|will) (an?|the) (async|helper|function|method))'

# section banners
rg -n '^\s*(//|#|/\*)\s*[=\-*_]{3,}'

# emoji + fancy unicode (comments, strings, identifiers)
rg -n '[^\x00-\x7F]'

# debug residue and test skips
rg -n '\b(console\.(log|debug)|debugger|print\()|\b(it|test|describe)\.(only|skip)\b|\bfdescribe\b|\bfit\('

# unowned TODOs
rg -n 'TODO|FIXME|XXX|HACK' | rg -v '(TODO|FIXME|HACK)\s*[:(]?\s*[A-Z]{2,}-\d+|@\w+'

# commented-out code (heuristic: a comment line ending in a statement terminator or brace)
rg -n --pcre2 '^\s*(//|#)\s*[\w\.\(\)\[\]"'"'"' ]+[;{}]\s*$'
```

Language-specific dead-code detectors beat greps when the repo already has one: `knip`, `ts-prune`, `depcheck`, `vulture`, `deadcode`, `cargo +nightly udeps`, `go vet`, `ruff --select F401`.

## Overall hygiene checklist (the second half of the pass)

Comments are the loud part; these are the rest of the tells. Report anything you don't fix.

| Area | Check |
|---|---|
| Naming | Names that describe the mechanism (`dataHandler2`, `processData`, `utils.ts`) instead of the domain. A comment that exists to translate a bad name means rename. |
| Dead weight | Unused imports, exports nobody imports, an abandoned feature flag, a config key nothing reads. |
| Duplication | The same helper implemented two or three times. Consolidate onto the existing one; don't invent a fourth. |
| Debug residue | Stray logs, `debugger`, commented-out experiments, a hardcoded localhost URL, a test pointed at prod. |
| Test hygiene | `.only` / `.skip` without a reason, tests that assert nothing, snapshot files for deleted components. |
| Secrets | Tokens, keys, real hostnames, or internal URLs pasted into comments or fixtures. Stop and flag - do not commit, do not "clean it up" quietly. |
| File placement | A file dumped at repo root or in a grab-bag `utils/` when the repo has a home for it. |
| Error handling | Catch-log-rethrow with nothing added; a swallowed error with an empty block; a generic `Error` where the repo has a typed one. |
| Docs drift | A README or runbook that the change just falsified. Fix it in the same pass. |

## Report format

```
Scope: <N files> from <base>..HEAD

| File:line | Tell | Action |
|---|---|---|
| src/foo.ts:12 | narration | removed |
| src/foo.ts:44 | changelog comment | removed |
| src/bar.ts:8  | why-comment, ticket link | kept |
| src/baz.ts:91 | unused export | removed, no callers (rg + knip) |

Left for a human:
- src/net.ts:203 - guard looks dead but three callers are dynamic; needs someone who knows the boot path.

Verified: pnpm lint, pnpm typecheck, pnpm test - all pass. Comment-only commit is a no-op to the suite.
```

## Anti-goals

- Not a bug hunt - that is `/code-review`, `pr-review`, or `bug-bash`.
- Not a refactor or simplification pass - that is `/simplify` or the `refactoring-expert` agent. This skill does not restructure logic; the one exception is a rename that makes a comment unnecessary.
- Not a formatting run.
- Not a docs rewrite - prose style is the writing-style rule; this is about what the code says about itself.
- Not a comment ban. A codebase with zero comments has usually lost the why-comments too, which is a worse failure than the one this skill fixes.
