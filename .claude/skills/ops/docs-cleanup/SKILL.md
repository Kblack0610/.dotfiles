# Docs cleanup

Docs rot where no linter looks: the prose stays well-formed while the code, the paths and the systems move out from under it, and a session acts on what the doc says. A doc that names a file that is gone, a bug that is fixed, or a system that was retired is what a session acts on when it "hallucinates". This skill audits truth, not form, at three scopes: **Pass** (the agent corpus: skills, rules, memory, anchors, lessons, the knowledge base), **Repo** (one repo's docs against its code) and **Skills** (judgment on the skill corpus, and new skills).

The pass method (finding shape, in flight, baseline, re-measure, report, proposals) is `~/.local/src/docs/analysis-streams.md`; read it first. `skill-drift` counts, `update-rules` picks the rule layer, `dotfiles-land` routes a change between the two dotfiles repos, and the skill standard is `~/.local/src/docs/skills.md`. The nightly `docs-cleanup` runner (`agentctl list --md`) takes the counts and queues a Pass when there is drift.

## Scope and triggers

- Pass (the default, so a bare `/docs-cleanup` runs it): the nightly queue item, or the human asks for a docs cleanup or "docs pass N"; sessions keep acting on things that are no longer true (a retired runner, a moved path, a fixed bug).
- Repo: "are our docs accurate", "do the docs match the code", "audit the docs", "is the README still right", "our docs are stale"; after a change that reverted something the docs explain (the highest-yield moment); before a doc set goes to a client or a security review.
- Skills: "audit the skills", "are my skills stale", "what skills am I missing", "make a skill for this", "new skill"; the CLAUDE.md skill-candidate rule (a workflow recurs 3+ times).

Not for writing or placing a doc (`docs-write`), code cruft over a window (`day-log`, Review), live UI (`ui-audit`), what code says about itself (`code-hygiene`), or a rule the human just gave (`update-rules`).

## The prime rule

A claim is verified against the code at the merge base (`test -e`, `command -v`, `--help`, `git show origin/<base>:<file>`), never against another doc: two docs agreeing is usually a copy. Resolve the base first and confirm the branch you are on. If a claim's truth differs between the base and an open PR, say so in the finding: "the docs describe what PR #N is about to change" has a different fix (wait, or land them together) from "the docs are wrong".

## Pass: the agent corpus

Fixes one area per PR and queues no next pass (the nightly runner does).

1. **In flight first,** per the method, on both dotfiles repos, plus `git -C ~/.agent status` for files another session has dirty.
2. **Baseline, from the scripts only.** The runner's inbox (`~/.local/state/agentctl/docs-cleanup/<date>/`) holds `skills.json` (`skill-drift --json`), `docs.json` (`skill-drift --docs --json`), `dups.json` (`skill-drift --dups --check --json`: restated instructions, the pairs over `dup_pairs_max` are the drift; delete the loser's line, then lower the row), `lessons.tsv` (bytes per lessons file), `chains.tsv` (`lessons chains`: each entry whose supersedes marker names an older one, or a key no entry carries any more), `retired.tsv` (`knowledge-retired`: hosts that left the home-config inventory and commands deleted from `.local/bin`, from git history) and `knowledge.json` (`notes knowledge lint --json --retired retired.tsv`: drift per class in `~/.notes/knowledge`). By hand, run the same commands.
3. **Inventory, worst first.** Group the findings by the layer a session reads soonest: `MEMORY.md` index lines and memory files (load every session), the rule files (both CLAUDE.md, `~/.dotfiles-private/AGENTS.md`), anchors, skills, `~/.local/src/docs` and the agentctl runbooks, then lessons. For each finding: doc and line, what it says, what is true now, and the action. A dead path is a lead, not the whole finding: read the sentence around it, since a moved file usually means the claim moved too. Also grep each layer for systems named as retired in the rules (the per-Stop LLM judge, Obsidian, waves, board-runner) still written as live. Every memory file gets a prime-rule read each pass, flagged or not: a memory about a bug that has since been fixed names only live paths, so skill-drift never flags it (pass 1 found 25 of 38 dotfiles memories stale, most with no dead path).
4. **Fix by cause, one area per PR.** Skills and rules: a branch per area under `~/.worktrees/`, routed by `dotfiles-land`, rule edits through `update-rules`, a skill's `metadata.reviewed` bumped only after checking it. Memory files and anchors: edit in place; delete a memory whose whole fact is a fixed bug and drop its index line.
5. **Lessons: rewrite, never pile up.** A correction chain becomes one entry saying what is true now. The replaced text and any entry about a retired system move to `~/.agent/lessons/_archive/<project>-superseded.md` with a line naming what replaced it; nothing is deleted. Work through the chains `chains.tsv` lists first: each line is a corrector and the exact lesson its `<!-- supersedes:KEY -->` marker names (`lessons key FILE LINE` prints a key), so fold the two, archive the old text and drop the marker; a target of `-` is a marker whose entry was reworded or archived, so re-point it or drop it. Then the dead-path entries `docs.json` lists, at most 40 entries a pass so each one is checked. An entry that only says "correcting" or "SUPERSEDED" with no marker is a lead to read, never proof of a live chain.
6. **Knowledge: fix through its one writer.** Skip this step when another session is restructuring the vault (`git -C ~/.notes status --porcelain knowledge` is dirty, or an item on the knowledge base is running) and say so in the report. Otherwise work `knowledge.json` class by class and change pages only through `notes knowledge apply <ops.json> --retired <retired.tsv>`, never by hand, so the registry, shrink guard and retired check hold. A `retired_host` or `retired_command` line is a fact to retire: say on that line that the thing is sold, retired or replaced (and by what), or drop the claim; apply refuses an op that writes one as live. A `dated_slug` page moves to its undated slug under its registered domain with its links updated; an `unregistered` domain is a `domains.toml` row only when its pages are a real domain, else the pages move.
7. **Re-measure** with the same commands, `wc -c` on the lessons files, `lessons chains | wc -l` and `notes knowledge lint`.
8. **Report** in `~/.agent/plans/dotfiles/docs-cleanup.md` (current pass only; git history in `~/.agent` keeps the old ones) per the method, each fix naming its PR or file, plus archived (count per lessons file). Then close the item per the method.

## Repo: one repo's docs against its code

Read-only by default; proposes a tiered fix set and confirms before editing. Three tiers, most damaging first.

1. **Tier 1, correctness: claims the code contradicts.** Pick the canonical docs (the ones the index says to read first, specs, runbooks opened under pressure) and extract every load-bearing assertion, in this order: behavioral claims about a flow ("on X the system does Y"; read what the named function does now); claimed safety nets and controls (a doc promising a mitigation that does not exist stops someone looking for a real one; check these even unprompted); stated rationale (it rots quietest, and a reader who believes a disproven reason reintroduces the problem); named identifiers (constants, env vars, paths, ports, routes); deprecated things still described as live (grep the schema for `deprecated`, then the docs for the name). Report each as the pair: what the doc says, what the code does, file:line of both, and what a reader would do wrong. Fix the rationale, not just the claim, and say plainly when an old reason was wrong. Follow the defect class: grep the whole doc tree for a wrong claim once found; the copies in ops and security docs matter most.
2. **Tier 2, navigation: mechanical, read-only.** Broken relative links (`for f in $(find docs -name '*.md'); do d=$(dirname "$f"); grep -oE '\]\(\.{0,2}[^)#:]*\.md' "$f" | sed 's/^](//' | while read -r l; do [ -e "$d/$l" ] || echo "BROKEN $f -> $l"; done; done`) and orphan docs the index never reaches (`cd docs; for f in $(find . -name '*.md' | sed 's|^\./||' | grep -v '^README.md$'); do grep -q "$f" README.md || echo "ORPHAN $f"; done`). Separate deliberate exclusions (generated files, frozen archives, scratch, a directory link) from real gaps, and get the deliberate ones written in the index as exclusions so the next sweep is clean.
3. **Tier 3, gaps and self-contradictions.** List the system's real components from the source and ask which have no doc home; the fix is a map that links out, never a seventh copy. Two docs, or two halves of one, that disagree resolve into one statement that keeps the correction's evidence; if the old claim shaped a design still in the code, name it as a known issue rather than deleting it.
4. **History.** A doc describing what was done and why at a point in time gets a dated superseded note scoped to the half that changed, not a rewrite; a doc stating current behavior is corrected outright. Respect a runbook banner's scope and say so in the PR.
5. **Output.** Tier tables, most damaging first, each finding naming the doc, the source that contradicts it, and the reader consequence; then the fix set, confirmed before editing. A derived copy (a deck, a wiki mirror generated from `docs/`) is regenerated in the same change, never hand-edited.
6. **Verify.** Run the repo's own doc checks and read how each scopes itself: a diff-scoped checker compares `<base>...HEAD`, so commit before checking. A line-scoped checker flags every violation on a line you touched; convert the file whole in its own commit. Re-run both Tier 2 sweeps, grep each corrected claim's old wording across the tree (derived copies too), check every identifier a new map cites, and say how many assertions in which docs were checked: nothing here proves a doc complete.

## Skills: audit, apply, propose

A `SKILL.md` is prose an agent obeys, with no compiler: when a path moves or a sibling retires nothing fails loudly, and the session improvises. Never trust a skill's account of itself. No change reaches a skill without a reviewable diff: the nightly runner fixes the mechanical findings by PR (Pass above); the verbs here are the judgment layer, a human confirming each change.

1. **`audit` (default, read-only), four layers.** (1) Filesystem: `skill-drift --json`. Environmental findings: `DEADPATH` (a `~/` path that does not exist), `NOCMD`, `UNDEPLOYED`, `GHOST` (bulleted in CLAUDE.md, absent from disk), `STALE` (`metadata.reviewed` past 180d), `UNUSED`, `PROMOTE`, `LISTBUDGET`; static ones from `skill-drift --lint .` (the checks `skills.md` names, CI-gated, old debt frozen in `tests/skill-lint.baseline`). It reports all findings and marks which are `new` against `~/.agent/skill-drift.baseline`; read the whole set. `STALE` is fixed by re-verifying the claims, then bumping the date, never the date alone. `UNUSED` is a signal, not a verdict: a release runbook is meant to look idle; cross-check overlap first and never propose deleting on `UNUSED` alone. Find where a `DEADPATH` went (`fd` across both repos) before proposing a fix. (2) Lessons: `~/.agent/lessons/{project}.md` (and the `~/.agent/evals/{project}/` archive): a correction whose cause was a skill saying something untrue is a skill bug to patch at the source; a manual workflow recurring 3+ times with no skill is a `propose` candidate; a lesson contradicting a skill's procedure is a finding. (3) mem0 (`mem0-ops`): a stored preference a skill still contradicts. (4) Descriptions: overlapping triggers with no sibling clause, triggers that do not match how the user phrases it, a stale "Do NOT", a description of the implementation rather than when to reach for it. Write `~/.agent/plans/dotfiles/skill-refine-{YYYY-MM-DD}.md`: a findings table (skill, type, severity, what, proposed fix; a fix tries delete, merge into a sibling, a pointer to the owning doc, and new text last), proposed diffs for the mechanical ones (not applied), skill candidates, and a verified / unverified split. Rank by blast radius.
2. **`apply` (interactive only).** Re-verify each finding of the latest report first; walk them in rank order, showing each diff and confirming. Skill prose: edit the `SKILL.md`; a `GHOST`: `update-rules`; `UNDEPLOYED`: `skill-deploy`. Re-run `skill-drift`; refresh the baseline (`skill-drift --write-baseline`) only when the fixed set is the accepted state. Land via `dotfiles-land`: public and private are two PRs.
3. **`propose`** (headless: write the proposal to the report, never a skill file). Name the evidence (the sessions or lessons that show the repetition), confirm scope and name with the user, and never auto-create a skill file. The name takes the prefix its system's skills share and `metadata.system` names that system. Copy `~/.dotfiles/.claude/skills/SKILL-TEMPLATE.md` to `.claude/skills/{category}/{name}/SKILL.md` (`dotfiles-land` picks the repo). Landing links it (`dotfiles-autopull` runs `skill-deploy`); never hand-write the symlink. CLAUDE.md names it only when it collides with or replaces a skill, and a skill it replaces is deleted in the same PR. Run `skill-drift --lint .` before the PR.

`*.example.internal` hostnames, `AcmeCorp` and `YYYY-MM-DD` are deliberate sanitization in the public repo, not drift; never "fix" them into real names.

## Do NOT

- Do not verify a claim against another doc; two docs agreeing is usually a copy.
- Do not delete a lesson or silence a finding with `skill-drift: ignore` (without a stated reason) or a weakened check to make a number drop; move it to `_archive/` or fix the claim or the check's logic.
- Do not edit a `SKILL.md` in a headless run outside the Pass's mechanical fixes, and never create or delete a skill without the human's yes.
- Do not touch auth tokens, history, logs or sqlite state, and do not edit mem0 (its queue stays human-gated).
- Do not hard-wrap prose in a skill or doc.
