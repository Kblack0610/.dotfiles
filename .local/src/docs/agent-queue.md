# agent-queue

`agent-queue` (`.local/bin/agent-queue`, tests `tests/integ/agent_queue.bats`) is the only program that writes the work queue's store. This doc is the reference for the verbs sessions and operators use (the `case` in the script is the complete list), kept beside the code so a change to the code and to this page is one PR. The queue's design, the item's fields, the states, the order and tags, Admission, the intake channels and the store sync are in `~/.config/agentctl/QUEUE.md` (the private overlay), which this page cites by section name. How a queued item gets started: [fleet-dispatch.md](fleet-dispatch.md).

| Verb | Does |
| --- | --- |
| `add [--project P] [--mode oneshot\|plan] [--priority P] [--weight heavy\|light] [--tags T] [--after S[,S...]] [--from F] [--agent A] [--slug S] [--title T] [--row ID] [--running [--session S]] [--repeat] [task...]` | Write an item; the task comes from args or stdin. One that carries a gate writes no item: the gate goes on its board row and the add exits 5 (QUEUE.md "Order and tags"). `--row` works a row already filed: it starts that open row on the agent board of the project its id's code names (among projects sharing the checkout, so `project:` can change) and records it in `row:`, with `from:` still the origin. It refuses, writing nothing, an id that is not `<code>-<N>` or not open there, a row a live item names (`claim` that item instead), a project with no board, and `--epic`, `--want`, `--from board:` or `canary` beside it. With no `--row`, `--epic` (its own or the plan's `epic:`), `--want` or earlier row for the slug, a title whose subject is one open row id links that row, and its code can change `project:` the same way: the subject is the title's first word (before a colon, a space or the end) or an id in brackets anywhere, and two different ids name none. Unlike `--row` it never refuses: a closed or claimed row, or an id elsewhere in the sentence (a mention), files a story as before. A plan's phases take no `--row`: each is its own story under the plan's `epic:`, since one row cannot close once per phase. `--title` writes the one-line `title:` the views show (fleet-dispatch passes the board row's text). The project defaults to the repo it runs in, and must reach a checkout by fleet-dispatch's rule: a game inside a repo (a `trackers` entry with `repo`) is filed as itself, an alias as its project, and a notes-only project is refused. `--running` writes into `running/` (a session recording itself: its `session:` and the `window:` it runs in), and warns, adding it anyway, when another active item of the project holds the area its title names (dispatch starts no second session on a held area). With no `--weight`, an item is heavy when its project's checkout is a Unity project (`ProjectSettings/ProjectVersion.txt`), its mode is plan, or it carries two or more phases, else light; `list --json` gives an item with no `weight:` line the same answer |
| `add --plan <plan.md> [--dry-run] [--project P] [--priority P] [--tags T] [--after S[,S...]] [--slug prefix] [--from board:<project>:<id>] [--repeat]` | One oneshot item per unchecked `## Phases` line whose wait is met, slug `<prefix>-p<N>` (prefix: the plan's file name); a phase that waits on one not landed is filed as its board row gated `#after/<the row it waits on>` (`held <slug> -> <board>:<id>`). Each waits on the one before and the first on `--after`, unless its line says `(independent)` (after `--after` alone) or `(after N)` (after phase N's item); an unmarked line keeps the chain, and a marker on a `(with N)` line, `(after N)` naming a deferred or later phase, or `(independent)` with `(after N)` refuses the plan, naming the line. A phase line that says `takes <row-id>` or `takes board row <row-id>` is filed at the higher of the plan's priority and each taken row's (one `notes board --json` read, refused when it fails; a row not open is warned about and gives no priority), `--dry-run` prints `takes <ids>` and `priority <p>` on its line, and `agent-land --plan --phase` closes those rows with the phase's own PR (`phase_takes` in `plan-phases.sh` is the one reader of the marker; the plan's `rows:` line still closes with its last phase). While each open phase takes a row still open on some board, `ask-sweep` files no plan row for it, since those rows carry the work. A phase's newly filed story row is tagged `#takes/<id>` for the row it takes (ar-3886; an open twin row it links keeps its own tags); `--dry-run` files none. The brief says read the plan whole, do only this phase to merged, tick its box, and stop if what it waits on is missing. Each item's title is `<plan> P<N>: <phase name>` (joined phases `P4+5`, names joined with `; `). A phase line with `(with N)` joins phase N's item when N is open, for phases that share a branch. Every slug is checked before anything is written, and a plan another active item already names (its `plan:`, or a task naming the plan's file; the calling `$AGENT_QUEUE_ITEM` aside) is refused, so a plan is queued once, except a chain an earlier add of the same plan left short (a busy lock stopped it part way, ar-2922): the same add keeps the phases already queued and queues the rest; `--dry-run` prints the items. `--from board:<project>:<id>` (dispatch's pull only, else exit 5 and nothing written) puts that row on the plan's `rows:` line and files the phases `from: auto:plan-row`. `fleet-bench forecast` counts each item's `phases:`. A second add while a gated row naming the plan is open refuses. A session whose remaining phases are items, or gated rows naming the plan, reads DONE in `fleet-sessions` once its own phase lands; the shepherd tells a LANDED session holding the rest of its plan to run this and wind down |
| `list [--json] [--state S] [--date D]` | Items grouped waiting, review, running, queued, each in queue order; a held item says why (`after x` or `after x y`, the slugs still live, or `after x closed failed, dead: ...` when one named slug closed not ok, `at:18:00`, `pr:Org/repo#12 not merged`, `nightly:repo (multi.yml running)`, `ask:a1=a (pending)`, `hold:mac-desktop (since <t> by <session>: <reason>)`) |
| `next [--json]` | The first runnable queued item, or exit 1 |
| `show <slug> [--json]` | One item, header and task; falls back to the latest finished one |
| `mine [--session s]` | The item whose `sessions:` holds `$CLAUDE_CODE_SESSION_ID`, else the running item that records this tmux session (a waiting or review one is an earlier conversation's); exit 1 none, 2 more than one |
| `claim <slug> [--sid id]` | Add a Claude session to `sessions:`; a no-op when it is there. The caller's own claim (no `--sid`) of a queued item takes it: it moves to `running/` with the `session:` and `window:` `add --running` records, so dispatch never starts a second session on it, and warns as `add --running` does when another active item holds its area. A `--sid` claim is a starter's record and moves nothing |
| `cancel <slug> [--why T] [--ask ID]` | `done/` with `status: cancelled`, `cancelled_by:` (the session id, else the item slug the caller works; none from a bare terminal) and `cancel_why:`, and the same `by` and `why` on the `item-cancelled` event. `--why` is required whenever `$CLAUDE_CODE_SESSION_ID` or `$AGENT_QUEUE_ITEM` is set, so a cleanup cannot cancel without saying why. Work the human asked for needs `--ask` from such a caller (Cancelling the human's work, below). A running or waiting item closes what it owns, through `tmux-close`: the `window:` it recorded, else its session when fleet-dispatch made it (`origin:` set), else nothing. A session a world manifest declares (hub `dotfiles`) is never killed |
| `bump <slug> <priority>` | Change priority. On an item with a board row it retags the row (`set <slug> priority=` too), since the order reads the row. Bump to urgent never lifts an `after:` hold: on an item queued held before ar-3121 it names the hold and the `set <slug> after=` that lifts it. Held work is a board row, which bump (a queue slug) does not reach: release it by taking its tag off the row |
| `set <slug> <key=value>...` | Record dispatcher fields (`started`, `session`, `account`, `plan`, `pr`, `note`, `status`, ...). `slug` and `queued` are what the item is and cannot be set; `set` refuses any key outside its settable list |
| `retask <slug> [task...]` | Replace a queued item's task (args, or stdin like `add`), the correction for a task holding a wrong fact, since the task is the session's brief. An item with a `row:` has that row's brief rewritten first (`notes ptask edit <id> --brief`), then its body, so the next promote reads the corrected brief; a row that is not open refuses it and writes nothing. Only the body changes: every header stays, so `title:`, `row:`, holds and `plan:`/`phases:` do not move (`set type= area=` when the kind changes). An item with no `title:` shows the new first line as its title, and the board row keeps the title it was filed with. Refused unless queued (a requeued item is accepted: its next session reads the new brief); no task, or no active item, exits non-zero |
| `move <slug> <state> [--status S] [--why T] [--ask ID] [--if S]` | One state change, stamping `started`, `waiting`, `review` or `finished`; `running` from `queued` refuses an item whose hold is pending (an `after:` slug live or closed other than ok, or a tag gate not clear) and names it, as `add --running --after` refuses until each slug closed ok and `fleet-dispatch start --item` refuses before it launches; a resume from `waiting` or `review`, and the move that records a launch (a queued item with `session:`, set by `start`), read no gate (ar-3260; `tests/integ/agent_queue.bats`); `done` needs a status, and `done --status ok` refuses an item with `pr:` and no `merged:` (agent-land, or reap on the merge, writes it; `tests/integ/agent_queue.bats`); `done --status ok` on an item with a `row:` and no `pr:` closes that row with `notes ptask done --proof item:<slug>` (a row already closed is left alone, a failed close warns). `--if` is a compare-and-set: the move happens only while the item is still in that state, else exit 3 and nothing changes. `--why` and `--ask` are cancel's: they are taken only with `done --status cancelled`, which records and guards as `cancel` does, and are refused on any other move |
| `return <slug> --why T [--ask ID] [--drop]` | Send an item back to its board: closed cancelled with `end_reason: returned` and its row un-started, and every queued item `after:` it (transitively) goes back with it (`cancel_cause: returned with <slug>`), never left dead. A plain return of an item with a board row is not held: the row keeps its brief and takes the gates the item still waits on (`#after/<row>` for each live `after:` item, and each hold tag). With `--drop`, or for an item with no row, the cancel guard holds it before the first item closes, so one `--ask` must name each such slug; a plain return records a given `--ask` without checking it. `--drop` drops each row (`notes ptask drop`) instead of un-starting it, the human's drop of a chain. Exit 1 when a row stayed started |
| `requeue <slug> --hold <resource> [--class <class>] \| --ask <id>[=<option>[+<option>]]` | Send an active item back to its board row behind that agent-hold resource or that pending agent-ask: the item gains `hold:<resource>` (with `--class`, its one `desk:<class>`, replacing the last) or `ask:<id>`, its row takes the gate (`#hold/<resource>`, `#desk/<class>`, `#ask/<id>[/<option>...]`), and the item closes `cancelled` with `end_reason: returned`, its calling session left open. Its lane run is dropped unreported, as a cancel's is, so model-lane is not told a redo. Refuses a resource that is free (claim it instead), an ask already answered, and an item with no board row. `fleet-dispatch reap` requeues a session that ended on a pending ask the same way |
| `handoff <slug> --note <file> [--dir <checkout>]` | Pass a running item to a fresh session to keep context small: the checkout (`--dir`, else the cwd) must be clean and its head either on the trunk or on a named branch whose origin tip it is, and that branch becomes `salvage:` unless the item has a `pr:` or the trunk holds the head, which clear an older `salvage:` instead. The note becomes `handoff:`, `handoffs:` counts up, and the item goes back to `queued` with `end_reason: handoff`, an unrated end, so model-lane is not told a redo. Refuses an empty note or one outside `$HOME`, an item not running, and one at `AGENT_HANDOFF_MAX` (2). The long-session-handoff hook (`~/.claude/hooks/`) tells a dispatched session on a pilot repo when; the session then ends itself (`tests/integ/agent_queue.bats`, ar-2777) |
| `gate [--json] (--all \| <tag>...)` | Each board gate tag clear, pending (why, in `hold_for`'s words) or dead (it can never clear: take it off the row, or settle what it names); any other tag `none`. `--all` reads every gate on the open rows, fleet-dispatch's one call a pass. Exit 3 unless every gate is clear |
| `lock-miss [--hours H] [--max N]` | One line: the queue lock timeouts `lock-miss.jsonl` logged in the last H hours (1) against N (3), with the latest one's command and caller; exit 1 over the bound, 2 when the log cannot be read. The `queue-lock-miss` watch runs it (ar-4471) |
| `reopen <slug> [--to running\|waiting] [--why T] [--unland <owner>/<repo>#<N>]` | Put back the latest done item with that slug, closed by mistake (a reap that read a live session as gone, ar-900): to `running/` (or `waiting/`) with `session:` and `sessions:` as they were, `status:` and `finished:` dropped, `note:` saying why and keeping the close's note, and its board row started again through `notes` once the queue lock is let go (a row that will not start exits 1). A `failed` close reopens as it is. An `ok` close reopens only with `--unland`, naming the PR it closed on that was not its work (agent-land took a side PR from another repo, ar-1031): that PR comes off `pr:` and `merged:` in step (and `closing_pr:` when it was that one), and the row reopens through `notes ptask reopen <id>`, its proof off, before it starts; items `after:` it that the close released stay started. Without `--unland` an `ok` close is refused (new work is `add --repeat`), and so is a slug still active or a `cancelled` close (the cancel closed its session; add it again) |
| `admission [--json]` | The runnable count an add is held against, the cap (`AGENT_QUEUE_CAP`), and the adds held in 7 days; `--json` adds `day`, the same count over 24h with the items per reason; see QUEUE.md "Admission" |
| `stats [--json] [--since D]` | Active counts, outcomes, wait (queued to started; median and p90 over items that waited, `started_at_once` counted apart) and run (started to finished) in minutes, by project, source and tag; `sitting`: queued items that can start now (count, median age, the 3 oldest) and held ones by kind; `added_per_day` next to `per_day`; `chain`: handoff (an `after:` item from its predecessor's finish to its start, 0 counted) as n, p50 and p90 by priority, over the window and the last 24h (`h24`), which `fleet-bench pipeline --check chain-lag` bounds |

## Cancelling the human's work

Work the human asked for (`from: human`, or a `requested` tag from a #requested row) is refused to `cancel`, `move ... done --status cancelled`, `return --drop` and a `return` of an item with no board row from a session or script (`$CLAUDE_CODE_SESSION_ID` or `$AGENT_QUEUE_ITEM` set) unless `--ask <id>` names an answered ask, so a cleanup hands the human's work back as an ask instead of dropping it (`tests/integ/agent_queue.bats`, the `--ask` cases). What the guard checks, exactly:

- The ask is `answered`, and its `answered_by` is `human` or empty (a legacy answer); a judge or shepherd answer is refused.
- The ask file contains the slug as a whole word (`grep -w`, so a hyphenated sibling such as `<slug>-2` also matches). It does not read which option the human picked: any answer counts, so post the ask as a question about cancelling that item.
- Once `--ask` is given it is checked on every item, human work or not. The ask joins `cancel_why:` as `(ask <id>)`.
- A caller with neither variable set is not held: the human at a terminal, and the Queue tab's button while the hub or agent-web was started outside a Claude session. A slug with no file left, closed in the chain record only, is not guarded.

A slug is matched by the item's `slug:` header, never by file name alone. Timestamps are UTC (`2026-11-03T18:40:00Z`), so jq can do the arithmetic. `AGENT_QUEUE_DIR` overrides the store's default directory, `~/.agent/queue/`; a bare session name in `session:` is on the world `tmux-world agents` names (`lab`).
