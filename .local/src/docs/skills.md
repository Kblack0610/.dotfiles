# Skill standard

What every skill, command and agent file holds to, one rule per line with its why. A rule that names a check is enforced by `skill-drift`, in every repo that calls `.github/workflows/skill-lint.yml`, and proven in `tests/integ/skill_lint.bats`; the rest are for the reviewer. Start a skill from `.claude/skills/SKILL-TEMPLATE.md`; `skill-refine` audits the corpus against this file.

- A skill's source is `.claude/skills/<category>/<name>/SKILL.md` in one of the two dotfiles repos, chosen by `dotfiles-land`, and `skill-deploy` flattens it to `~/.claude/skills/<name>/`; `dotfiles-autopull` runs it after every fast-forward. Why: Claude Code reads personal skills one level down, so categories exist in the repo only, and the two repos feed one namespace. Check: `BADMETA`, `CATCOLLIDE`, `DUPNAME`, `UNDEPLOYED`.
- Anything that points at a skill uses `~/.claude/skills/<name>/`, never a repo path. Why: that path survives a re-categorisation and a move between the repos, and a repo path breaks on both. Check: none; `DEADPATH` catches the path only once it is dead.
- Frontmatter parses as YAML and holds `name` (kebab-case, equal to the directory), `description` and `metadata.{category,tags,reviewed}`, with no version field. Use `description: >-` when the text holds a colon. Why: a parse failure silently drops every field, a name that disagrees with its directory changes what gets invoked, and git already answers what changed. Check: `NOFRONTMATTER`, `BADYAML`, `BADNAME`, `BADMETA`.
- `metadata.reviewed` is the date someone last checked the skill's claims against reality; bump it only after doing that, never for an edit. Why: it answers the one question git cannot, and a date that lies is worse than a date that is old. Check: `BADMETA` for the format, `STALE` past 180 days.
- A description plus `when_to_use` is at most 300 bytes, measured on the parsed value. Why: every entry shares one listing, so one long description costs another skill its own. Check: `LONGDESC`.
- A description is a trigger line: what it is in a few words, the phrases a user would type, then the sibling most often confused with it, in the form `<word>: <skill>` (for example `Ingest: playground-ingest`). Why: the router chooses on the description alone, and the sibling is what stops two skills answering one ask.
- The whole listing stays under its budget: 24 KB of names and descriptions from the deployed tree, which is the 30 KB shared listing less about 6 KB of built-in entries; a skill that applies only inside one kind of repo carries `paths:`, and an unfinished one `status: draft` with `disable-model-invocation: true`, so neither is listed until it is needed, and a skill the usage toggle keeps name-only (`skillOverrides`) costs only its name line. Why: past the budget the last entries arrive as a bare name, with nothing to say so. Check: `LISTBUDGET`, in the local report because only a deployed tree holds both repos. Test: `tests/integ/skill_lint.bats` "LISTBUDGET: a listing over the budget reports its size".
- A skill that stands in for a command sequence lists the hand-typed forms it replaces in `metadata.replaces`, one row each: `match` (a regex over the command as code), `use` (what to run instead), `mode: deny` once a script covers the form (`report` until then), and optional `where` (a cwd regex), `unless` and `why`. That frontmatter is the only list: `.claude/hooks/hand_methods.py` denies a `deny` row at call time, `claude-recall stats --kind bypass` counts the matching calls that ran (a hook-denied one did not), and `skill-drift` reports a skill sessions go around as `BYPASSED` and one nobody uses or bypasses as `RETIRE`. Why: a documented process that sessions can still retype by hand stays retyped (700 playground sessions in 30 days to 2026-11-09 typed the gate block the skill covers). Check: `BADMETA` (replaces). Test: `tests/integ/hand_methods.bats`.
- Every skill has a `## Scope and triggers` heading saying what it covers, when to use it and what is out of scope. Why: one fixed place to read that in any skill; `When to Use` is the retired form. Check: `NOHEADING`.
- SKILL.md stays under 500 lines; docs read on demand go in `references/`, templates it copies in `assets/`, and a script beside SKILL.md. Why: once loaded the body stays in context for the rest of the session, so every line is a recurring cost.
- A skill body is plain ASCII, with no em or en dash, arrow, ellipsis or comparison glyph, and holds no `$N`: write `${1}` in shell, `$(1)` in awk, and money in words. Why: the glyphs read as machine-written and get copied into everything the skill writes, and Claude Code replaces `$N` with argument N when the skill is called with arguments, so `/local-model label ...` read "It costs label". Check: `NONASCII`, `ARGSUB`.
- Commands (`.claude/commands/**/*.md`) and agents (`.claude/agents/*.md`) hold to the frontmatter, description and ASCII rules, as `command:<path>` and `agent:<name>`; an agent also needs `name`. Why: they share the listing and the parser with skills. Check: `NOFRONTMATTER`, `BADYAML`, `LONGDESC`, `NONASCII`.
- A project repo calls the workflow with `profile: project`: the rules above minus `metadata.*` and the category layout, with flat `.claude/skills/<name>/` accepted. Skills a tool generates stay out of git, so a Unity project with no others ignores `.claude/skills/` and its caller sets `allow-empty: true` and filters on `paths:` for `.claude/**` and the baseline. Why: those two only mean something in the dotfiles layout, a project's skills are listed like any other, and the Unity MCP plugin rewrites its own, so a hand edit does not last. Test: `tests/integ/skill_lint.bats` "project profile: a bad heading fails", "--allow-empty: a bad skill still fails".
- `tests/skill-lint.baseline` holds debt that predates a rule, as `TYPE|subject` lines, and it only shrinks. Delete a line when you fix its finding; a stale line is reported. A new check with debt to freeze says so in a commit trailer, `Skill-Baseline-Raise: <why>`, and a renamed skill clears its debt first. Why: a baseline that can grow is a way to switch a rule off. Check: `skill-drift --ratchet`. Test: `tests/integ/skill_lint.bats` "--ratchet: an added baseline line fails".

The global rule that proposes a recurring workflow as a skill is adapted from rebelytics/one-skill-to-rule-them-all (CC BY 4.0).
