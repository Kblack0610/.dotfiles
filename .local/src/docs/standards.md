# Agent runtime standards

The rules the agentctl fleet holds, one per line with its why and the test that fails when it breaks. Each is invariant or provisional, by the last rule below. The global rules link here; the shape is in `~/.config/agentctl/ARCHITECTURE.md` and the state words in `fleet-states.md` beside this file. Dashboards (the hub TUI, agent-web, waybar chips, Grafana) follow `dashboards.md` beside this file, every UI looks the way `ui.md` says, judges `judges.md`, and skills `skills.md`.

- A headless model run goes through `agentctl-run`, never `claude -p` directly; every launch outside it has a row in `~/.config/agentctl/PIPELINES.md`. Why: only `agentctl-run` applies the role (what it may do) and the route (which model and endpoint), so a direct call silently inherits whatever the calling shell has. Tests: `tests/unit/runner_contract.bats` "nothing in the repo launches a headless claude except agentctl-run", `tests/unit/pipelines_doc.bats` "every model call outside agentctl-run has a row, and every row is still one"; `tests/unit/consolidation_ledger.bats` "a direct claude -p fails the check until its file has a row in the launch table"; and `fleet-bench ledger --check` in the private repo's CI, which holds both repos to that table.
- A runner ends every pass with one `last-outcome` word from `WORKED NOOP BLOCKED FAILED STALLED`, written by `proof_report` or `proof_verdict` in `agent-proof.sh`. Why: `fleet-liveness` and the KPI table read that word, and a free-text verdict was invisible to both. Test: `tests/unit/agent_proof.bats` "proof_report records a word outside the vocabulary as FAILED, naming it".
- A session's bucket is computed once, by `fleet-sessions --write` into `~/.local/state/fleet/state.json`, and every view renders that document instead of recomputing it. Why: nine readers in eight vocabularies disagreed about the same session. Tests: `tests/unit/fleet_sessions.bats` "--write: the state document holds the --json rows, their activity, and pending asks"; `tests/integ/agent_mqtt_publish.bats` "each session carries its bucket from the fleet state document, joined by target".
- Provisional: a runner is one job class on one cadence. A new source or pass of a class that has a runner is a step of that runner (`STEPS` in its conf, run in order by `agentctl-steps`, each step keeping its own outcome); only a new cadence or job class makes a new runner. Runners and timers may only shrink: to add one, retire one or add a dated delta line to `~/.config/agentctl/ledger-baseline` in the same PR (its header has the format). Why: one runner per source split three job classes into 11 runners. Number: the runners and timers counts in `ledger-baseline`; confidence med; revisit when a runner's steps need different cadences or one step keeps holding the others back. Tests: `tests/unit/consolidation_ledger.bats` "a new conf fails the check and names the count that grew (negative control)"; `tests/unit/agentctl_steps.bats` "every step runs in order after one fails; each keeps its own word and the runner is FAILED, naming it"; and `fleet-bench ledger --check` in the private repo's CI (`.github/workflows/ledger.yml`) on each PR and daily.
- Session quality is what `agentctl-session-outcomes` counts and `fleet-bench kpi` reports; no model scores a transcript. Why: the per-Stop judge failed on 59% of turns over 30 days and scored 10/10 on 78% of the rest, so nothing could act on it. Test: `tests/integ/stop_hook_quiet.bats` "no post script calls a model: the session eval is session-outcomes, not a Stop-time judge".
- Every merged PR has an agent-queue item: `agent-land` is the one lander (forge-guard denies `gh pr merge` and a raw PR-API merge) and refuses a PR with no item (`--item`, `AGENT_QUEUE_ITEM`, or the session's own `add` or `claim`; an item it was not given by `--item` takes only a PR it records or whose body names it on an `Item: <slug>` line). Why: the ledger is the one record of work, and a PR off it is one no reader can credit. Tests: `tests/unit/agent_land.bats` "no queue item: refused before any gh or git call, naming how to add one"; `tests/integ/forge_guard.bats` "gh pr merge outside a Forgejo checkout is denied, naming agent-land with the PR and repo".
- A started `[/]` agent row implies a queue item, and a `run:` in its marker that the item has started (`agent-queue` writes both, so the sweep puts it in Now, else Next up): `fleet-dispatch reap` un-starts a row no open item names once it has stayed orphaned `DISPATCH_ORPHAN_HOURS`, and a human-sheet row too while its marker carries `run:`, never one the human flipped by hand. Why: a `[/]` with nothing behind it reads as work in flight and keeps dispatch off the row. Test: `tests/unit/fleet_dispatch_reap_restore.bats` "reap: an agent row started with no queue item is un-started only once it stays orphaned DISPATCH_ORPHAN_HOURS", "reap: a human-sheet row the fleet started is un-started once it stays orphaned DISPATCH_ORPHAN_HOURS (ar-1260)" and "reap: a human-sheet row with no run: is the human's even when an ended item named it, and a live item holds a run: row (ar-1260)".
- A closed entry carries merge proof: `agent-land` and reap close a backlog row only once the merge commit is proven on the base branch, and the row's marker names `pr:<N> commit:<sha>`; `agent-land` proves it before the item moves to done too. Why: a close on a PR's word alone counted reverted and never-merged work as shipped. Test: `tests/unit/agent_land.bats` "a merge commit not on origin/<base> is refused: the item stays open and no row closes".
- Every running item has an owner: a running item lists the Claude session ids that work it (`sessions:`, written by `add --running`, `claim`, and `fleet-dispatch start` for the id it launches with), so `mine`, reap and the outcomes join find it by id. Why: a running item with no session can never be nudged or credited, and a tmux name is reused across sessions; reap can only go by its PR and flag it (`ownerless_running`). Test: `tests/integ/agent_queue.bats` "add --running records the Claude session, a queued add does not; the row grammar's type and area; claim adds a session once"; `tests/unit/fleet_dispatch_start.bats` "start runs claude on the account claude-acct picks, for a brief and for a resume" and `tests/unit/fleet_dispatch_reap.bats` "reap: an item with no session settles by its PR, and is flagged once when it cannot".
- The room verdict (who may take an automatic start, and why not) is one field of one `claude-acct` row, the `room` object of `usage_json`; dispatch, the shepherd, the watches, `claude-acct status` and the hub and agent-web tabs print or branch on that field and never re-derive over pace, capped, slack or reserve from used and gone. Why: each reader kept its own rule, so an account read "over" on every dashboard while dispatch still started on it. Tests: `tests/unit/claude_acct.bats` "no second copy: the pace numbers and the room rule are written once, in pace.conf and usage_json"; the surfaces, `burn::tests` in hub-core and `tests/agent-web/fleet.test.mjs` "the accounts table prints claude-acct's room verdict".
- Provisional: `wt reap` is the only code that removes a worktree, and `wt gc` deletes the merged slot branches nothing checks out, with `-d`. Why: the WorktreeRemove hook ran a raw `git worktree remove` that skipped the pane, process and submodule checks, and merged `agent-N` branches piled up (11 in dotfiles, 5 in private on 2026-11-06). Number: 2 hand removal paths found; confidence med; revisit when a third caller of `git worktree remove` appears or the held count (P4 KPI) stays under 10. Tests: `tests/integ/worktree_create_hook.bats` "worktree-remove: an unlanded tree survives the hook, which reports the refusal", `tests/integ/worktree.bats` "gc: merged slot branches are deleted, an unmerged or checked-out one is not".
- Every rule is invariant or provisional. Invariant: safety and irreversibility only (never force push, Auth-State Safety, the secret scan, one PR per repo); a session never weakens one, and only the human changes one. Provisional: everything else; it carries the number it rests on (a number set in config is named, never copied: the row points at the knob and its measure reads it, and `fleet-bench rules --check` fails a bound copied from the file its measure reads), a confidence (high/med/low, from how often that number held) and a revisit trigger, and a session that finds the number moved queues a high-priority cleanup item to rewrite the rule and keeps following it meanwhile. Why: a rule that does not name its number cannot be told from a stale one, and only the irreversible ones are worth freezing. The register is `~/.config/agentctl/rules.jsonl`; `fleet-bench rules` re-measures it on the daily scorecard. Every rule row also names what holds it, `enforced_by`: `test:<path>[::<test name>]`, `hook:<path>`, `ci:<path>`, or `review` when only a reader does (a mechanism row is its own enforcer); `fleet-bench rules --check` fails a missing or dead one, and fails when the `review` rows differ from `rules-prose-baseline` beside the register, a count that only shrinks, so a new rule names its check or argues for one more prose row. A lesson the dream sweep finds a second time must carry `<!-- enforced_by:test:<path> -->` (or `hook:`, `ci:`) once a check holds it, and `rules --check` lists those that do not (`lessons seen`). Why: 277 rule rows named no check, and prose is what agents had already missed. Tests: `tests/unit/rules_register.bats` "register: every row is a whole row of its kind", its "enforcer", "review rows" and "lesson" cases, and its "restates" cases for the copied number.
- Provisional: every gate in code (a refusal, deny, block or route to the human in `.local/bin/agent-{ask,propose,queue,hold,land}`, `fleet-dispatch` or `.claude/hooks/`) is one register row with an `id`, `asked_by` (`ask:<id>`, `human:<their words or the rule that says it>`, or `agent:<PR or incident>`), `added` (the YYYY-MM-DD it first merged) and, when it refuses an agent or judge answer or files work to the human, `routes: human`. Its call site carries `# gate: <id>` on a line of its own above the refusal (one per hook file; `# gate: none` marks an added usage error), never inside a continued command. `fleet-bench rules --gates` fails a marker with no row, a hook that denies with none, and a refusal a branch adds with none; `--check` fails a `routes: human` row an agent added unless `remove_item` and an unexpired `remove_by` name the item that deletes it, and a gate row with no `added` date. `fleet-bench rules --new` lists the gates added in a window, agent-added first, and its `--line` is the one line the morning briefing and `day-log show` carry. Why: 62 of 89 blocks in the ask, queue, dispatch and hook tools were added by agents with no ask from the human, and nothing recorded who asked. Number: 49 gates registered on 2026-11-23; confidence low; revisit when a gate lands that the scan cannot see. Tests: `tests/unit/rules_register.bats` "rules --gates: a refusal the branch adds with no marker fails; a marker, gate: none or a comment passes" and "rules --check: a gate an agent added that routes work to the human fails unless an unexpired removal covers it" and "rules --new: the gates added in the window, agent-added first, newest first, each with its PR".
