# Agent runtime standards

The rules the agentctl fleet holds, one per line with its why and the test that fails when it breaks. Each is invariant or provisional, by the last rule below. The global rules link here; the shape is in `~/.config/agentctl/ARCHITECTURE.md` and the state words in `fleet-states.md` beside this file. Dashboards (the hub TUI, agent-web, waybar chips, Grafana) follow `dashboards.md` beside this file, judges `judges.md`, and skills `skills.md`.

- A headless model run goes through `agentctl-run`, never `claude -p` directly. Why: only `agentctl-run` applies the role (what it may do) and the route (which model and endpoint), so a direct call silently inherits whatever the calling shell has. Test: `tests/unit/runner_contract.bats` "nothing in the repo launches a headless claude except agentctl-run".
- A runner ends every pass with one `last-outcome` word from `WORKED NOOP BLOCKED FAILED STALLED`, written by `proof_report` or `proof_verdict` in `agent-proof.sh`. Why: `fleet-liveness` and the KPI table read that word, and a free-text verdict was invisible to both. Test: `tests/unit/agent_proof.bats` "proof_report records a word outside the vocabulary as FAILED, naming it".
- A session's bucket is computed once, by `fleet-sessions --write` into `~/.local/state/fleet/state.json`, and every view renders that document instead of recomputing it. Why: nine readers in eight vocabularies disagreed about the same session. Tests: `tests/unit/fleet_sessions.bats` "--write: the state document holds the --json rows, their activity, and pending asks"; `tests/integ/agent_mqtt_publish.bats` "each session carries its bucket from the fleet state document, joined by target".
- Runners, timers and direct headless launches may only shrink: to add one, retire one or raise `~/.config/agentctl/ledger-baseline` with a why in the same PR. Why: each new need had become a new script and timer, and nothing counted them. Test: `tests/unit/consolidation_ledger.bats`, and `fleet-bench ledger --check` on the daily scorecard.
- Session quality is what `agentctl-session-outcomes` counts and `fleet-bench kpi` reports; no model scores a transcript. Why: the per-Stop judge failed on 59% of turns over 30 days and scored 10/10 on 78% of the rest, so nothing could act on it. Test: `tests/integ/stop_hook_quiet.bats` "no post script calls a model: the session eval is session-outcomes, not a Stop-time judge".
- Every working session has an agent-queue item: the focus gate blocks a session that edits, commits or opens a PR with no item of its own (`AGENT_QUEUE_ITEM`, its own `add`, `claim` or `agent-land`). Why: the ledger is the one record of work, and a session off it is a merged PR no reader can credit. Test: `tests/integ/focus_gate.bats` "session: a PR with only a board write or a Focus item in progress blocks, once".
- A started `[/]` agent row implies an active item: `fleet-dispatch reap` un-starts a row no running or waiting item names once it has stayed orphaned `DISPATCH_ORPHAN_HOURS`. Why: a `[/]` with nothing behind it reads as work in flight and keeps dispatch off the row. Test: `tests/unit/fleet_dispatch.bats` "reap: an agent row started with no queue item is un-started only once it stays orphaned DISPATCH_ORPHAN_HOURS".
- A closed entry carries merge proof: `agent-land` and reap close a backlog row only once the merge commit is proven on the base branch, and the row's marker names `pr:<N> commit:<sha>`; `agent-land` proves it before the item moves to done too. Why: a close on a PR's word alone counted reverted and never-merged work as shipped. Test: `tests/unit/agent_land.bats` "a merge commit not on origin/<base> is refused: the item stays open and no row closes".
- Every running item has an owner: a running item lists the Claude session ids that work it (`sessions:`, written by `add --running`, `claim` and the preflight), so `mine`, reap and the outcomes join find it by id. Why: a running item with no session can never be settled or credited, and a tmux name is reused across sessions. Test: `tests/integ/agent_queue.bats` "add --running records the Claude session, a queued add does not; the row grammar's type and area; claim adds a session once".
- Every rule is invariant or provisional. Invariant: safety and irreversibility only (never force push, Auth-State Safety, the secret scan, one PR per repo); a session never weakens one, and only the human changes one. Provisional: everything else; it carries the number it rests on, a confidence (high/med/low, from how often that number held) and a revisit trigger, and a session that finds the number moved queues a high-priority cleanup item to rewrite the rule and keeps following it meanwhile. Why: a rule that does not name its number cannot be told from a stale one, and only the irreversible ones are worth freezing. The register is `~/.config/agentctl/rules.jsonl`; `fleet-bench rules` re-measures it on the daily scorecard. Test: `tests/unit/rules_register.bats` "register: every row is a whole row of its kind".
