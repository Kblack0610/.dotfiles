# Judge standard

A judge is a model call that decides something a human would otherwise decide: the answer judge (`ask-judge`, in `agent-ask`), the dispatch judge (`dispatch-judge`, in `fleet-dispatch`) and the ask sweep (`ask-sweep`). A scored runner is any other agent whose writes a counted outcome can grade: the inbox triager (`inbox-triage`) and planner (`inbox-plan`). Each is an agent with its own conf in `~/.config/agentctl/agents/` (what an agent is: `~/.config/agentctl/README.md`), and the conf's `SCORE=` names the truth source below that `judge-eval` scores it by. `judge-eval` is the one scorer; this file is what it holds a judge or a runner to. The fleet's other invariants are in `standards.md` beside this file.

## Ground truth per lane

| lane (`SCORE=`) | a verdict | right when | wrong when | not scored |
|---|---|---|---|---|
| ask-judge (`ask-answers`) | `judge` on the ask file, its rule and its `judge_call` | the human's answer is the option the judge would have given, or the human's review of a live answer is `judge_override: none` | the human answered another option, or overrode the live answer | gate asks, free text that names no option, `unclear-ask` deferrals, asks still pending |
| dispatch-judge (`dispatch-queue`) | the newest `dispatch` or `skip` line per row in `~/.agent/dispatch/verdicts.jsonl` | the started row's queue item ended `done ok`; a skip, when 48h pass from the first skip of its run with no hand start | its item ended failed or cancelled, or a later `failed` line names the row; a skip is a false-defer when a queue item for the row starts after it and fleet-dispatch's run did not start it (`origin` neither `run` nor `resume`) | rows still running, skips under 48h old |
| inbox-triage (`triage-untouched`) | each `filed` event in the notes ingest record (`notes log`) that no session or queue item wrote | 48h pass with no `edited`, `dropped`, `dup`, `rehomed` or `tagged` event on the row; the planner's own writes, the minute up to its `planned` record, do not count | one of those events inside the 48h | rows filed under 48h ago. A hand edit in an editor never reaches the record, so the score is an upper bound |
| inbox-plan (`plan-dispatched`) | the first `planned` event per row in the ingest record | a queue item for the row, or for a row the same run split from it (`#of/<id>`), starts before any re-split | a re-split comes first: a later `planned` on the row, or a row split from it by anyone else (`#of/<id>` added or tagged) | planned rows nothing has started |
| ask-sweep (`unrecorded`) | not recorded | - | - | everything: ask-sweep keeps nothing of its own, and the rows it files (`#requested`, each with its quote) are on the board, so `judge-eval` reports its calls alone until it records the row and whether the human kept it |
| shepherd, dream (no `SCORE`) | not recorded | - | - | everything. The shepherd's per-session ledger keeps only the last nudge and `watch.log` is keyed by tmux window, so "progressed before the next pass" needs an append-only nudge log keyed by session. Dream's promotions are prose in `DREAMS.md`, and accepting or rejecting a `mem0-queue.md` block deletes it alike, so "still present 14d later" and "accepted %" need a per-entry promotions record and a line per queue decision |

## Rules

- Judges are scored only by `judge-eval`. A dashboard or report shows its numbers and never counts again. Why: `agent-ask judge-report` and hub-core's own count both scored the answer judge, and they disagreed on in-session answers. Tests: `tests/unit/judge_eval.bats`, hub-core `fleet::tests::the_answer_judge_tiles_are_judge_evals_numbers`.
- A verdict is scored against its lane's ground truth above, never against a model's opinion of it. Why: a model grading a model scored 78% of turns 10/10 (the per-Stop judge retired 2026-10-28). Test: `judge_eval.bats` "the confusion matrix" and "dispatch-judge: the newest verdict per row".
- Scores count only verdicts made under the judge's current prompt (the git blob of its conf's `PROMPT`, the `prompt_sha` agentctl-run writes on the call). A changed policy starts the count again, and `--any-prompt` reads the history. Why: a score earned under an older policy says nothing about the one running now. Test: `judge_eval.bats` "--any-prompt also counts".
- A lane is scored only when its conf names a truth source in `SCORE=`: that is the list of lanes, and nothing else keeps one. Only a right or wrong rate is a score, never a volume. A runner's is the fleet-bench KPI `runner_score_<name>` (hyphens to underscores), its precision, shown only past the one bar below; the dispatch judge's skips add `dispatch_false_defer_pct` beside its precision, not a second dispatch score. Each lane's `score_7d` in `judge-eval --json` is that 7d value as a cell ("93% untouched", "n<30" under the bar, "-" with no counted outcome), which the Fleet Workers score column and the day-log runner rollup show. All are computed on read, with no store of scores. Why: a hard-coded lane list in judge-eval left every runner but the judges unscored (2026-11-05). Tests: `judge_eval.bats` "the lanes are the confs that name a SCORE", "inbox-triage negative control", `fleet_bench.bats` "kpi: a runner_score_ KPI", "kpi --check".
- A deferral the human answered with the recommendation is a false-defer, and it is reported beside precision. Why: precision alone rewards a judge that defers everything. On 2026-11-05 the answer judge had 8 scored answers and 47 false-defers. Test: `judge_eval.bats` "the confusion matrix".
- A live answer is labelled by the human's review: `none` is right, an override is wrong, and no review yet is pending. Why: the human never answers a live ask, so the review is its only label. Test: `judge_eval.bats` "the confusion matrix"; how a review is recorded: `tests/integ/agent_ask.bats` "override: ...".
- An answer typed in a session is scored when it names exactly one of the ask's options (agent-ask's `named_option`). The rest is counted as unscorable and never guessed. Why: a guessed label is an invented one. Test: `judge_eval.bats` "the confusion matrix".
- A gate ask (rule `gate`, no call) is not a verdict, and an `unclear-ask` deferral is the asker's fault. It is counted in `ask_unclear_pct`, never as the judge's false-defer. Why: the policy sends both to the human whatever the judge thinks. Tests: `judge_eval.bats` "the confusion matrix", `agent_ask.bats` "judge never sends a gate to the model".
- A failed call is an error: it is counted, left out of coverage's denominator, and never read as a deferral. Why: a timeout is not a judgement, and counting it as one would hide a broken judge behind a careful-looking one. Tests: `judge_eval.bats` "the confusion matrix", the `judge_errors` KPI.
- A type goes live on the human's call, by a PR to `LIVE_RULES`. `judge-eval` shows each type against one bar, `AGENT_ASK_LIVE_BAR` (30) scored answers at `AGENT_ASK_LIVE_PRECISION` (90%), with the 95% interval beside it, to inform that call. Why: the human took the recommendation on 92% of the asks the judge deferred, and holding every type until it had 30 scored answers kept a queue of asks the judge already called right. Test: `judge_eval.bats` "precision carries its 95% Wilson interval".
- A live type demotes when precision over its last `AGENT_ASK_LIVE_BAR` (30) live answers falls under `AGENT_ASK_DEMOTE_PRECISION` (85%), counted once it has `AGENT_ASK_DEMOTE_MIN` (10). Why: at about 90% a type almost surely meets one override in 30, so a first-override rule pulled every type within days; a recent window brings back a type that drifts without ending one that is right 9 times in 10. Tests: `agent_ask.bats` "override: ... one miss does not demote" and "override: a type demotes when precision over its last live answers ...".
- The answer judge reads the human's disagreements decided before the ask was posted, and one covering the same decision sends the ask to the human (`against-precedent`). Why: a disagreement changes the next verdict the same day with no rule written, and a replayed ask can never read its own answer. Test: `agent_ask.bats` "precedents: a disagreement older than the ask ...".
- Each verdict names its call (`judge_call`, one `calls.jsonl` line), so latency and cost per verdict are the call's, shared across the rows one call judged. Why: estimated costs drift, and a dispatch call judges many rows at once. Test: `judge_eval.bats` "dispatch-judge: the newest verdict per row" (cost per verdict).
- The judge KPIs (`judge_errors`, `judge_precision`, `ask_answered_pct`, `ask_false_defer_pct`, `ask_unclear_pct`) are fleet-bench KPIs with thresholds in `~/.config/agentctl/kpi-thresholds`, so `fleet-bench retro` files a row when one trips, and the `runner-score` Sentinel watch pages on a judge error in 24h or a `runner_score_*` or `*_false_defer_pct` KPI past (`fleet-bench kpi --check`). `judge_precision` is the lowest precision among rules with 10 or more scored answers. Why: a judge drifting wrong was visible only to someone who went looking. Test: `tests/unit/fleet_bench.bats` "kpi: the judge KPIs come from judge-eval kpi".

- Every answer verdict is listed, not only the misses: `judge-eval log`, and `verdicts` in `--json`, which Log's Judges' verdicts section shows on both surfaces. The list and its 7-day line take any prompt, because they say what happened rather than score a policy. Why: the human could only see where the judge disagreed, never what it said yes to or why it passed (2026-11-05). Test: `judge_eval.bats` "the verdict list".

## Replay

`judge-eval replay` scores a changed policy before it earns live labels: the real `agent-ask judge` over blind copies of the asks the human answered with an option, as the agent `ask-judge-replay`, whose own budget keeps it off `ask-judge`'s. The copies are then scored like any other verdicts, so its numbers are a replay's, never counted into the KPIs, and a run that would leak an answer sends nothing. Test: `judge_eval.bats` "replay".

## How the numbers are computed

Each verdict is one of: TP (answered, right), FP (answered, wrong), FN (deferred, but the human took the recommendation), TN (deferred, rightly), pending, unscorable, or an error.

| number | formula |
|---|---|
| coverage | answered / (verdicts - errors) |
| precision | TP / (TP + FP), with its Wilson 95% interval |
| false-defer % | FN / (FN + TN) |
| `runner_score_<name>` | the lane's precision, TP / (TP + FP), null under 30 scored |
| kappa | Cohen's kappa over the TP, FP, FN, TN table |
| p50, p95 | each scored verdict's call `duration_ms` |
| cost per verdict | each call's `cost_usd` divided by the verdicts it made, averaged |
| `ask_answered_pct` | asks the judge really answered (`answered_by: judge`) / (ask verdicts - errors) |
| `ask_unclear_pct` | `unclear-ask` verdicts / (ask verdicts - errors) |
