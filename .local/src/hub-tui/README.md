# hub-tui

`hub`, every hub board as one terminal app (ratatui) with a tab per board. It runs in the `hub:board` window (declared in `.config/tmux-servers/hub.conf`); tmux Prefix i lands on its Home tab, and the waybar load, CI and day chips open it on click. It reads through `hub-core`, the same crate agent-web's tabs use, so the terminal and the browser cannot disagree. It reads only, except the Sessions tab's session controls, which act on a session through `hub_core::session_actions` (the same actions as agent-web's session buttons), the Queue tab's cancel and priority keys, which run `agent-queue` through `hub_core::queue` (the same calls as agent-web's queue buttons), and the Board tab's add, start, done, drop, move, edit, release and open-sheet keys, which run `notes ptask --exact` through `hub_core::tasks` (the same calls as agent-web's Board tab). Trends live in Grafana; `o` opens the dashboard for the tab you are on.

Install: the installer's `build_local_rust_tools` builds it and links `~/.local/bin/hub`. By hand: `cargo build --release` here, then `ln -sf "$PWD/target/release/hub" ~/.local/bin/hub`.

## Usage

```
hub                              the board, on the Home tab
hub --tab fleet                  start on another tab (home, daily, queue, projects, sessions, infra, log, fleet; a retired name such as overview, focus, outbox, board, today, history, actions, forecast, watch, shepherd, jobs, ci or machines lands on its new tab, outbox on Daily's outbox)
hub --tab 'infra ci'             start on a section of Infra (health, red, machines, ci, jobs, cloud, governor); `--tab ci` is the same, and `jobs` opens the jobs table
hub --popup --tab queue          a floating window (the waybar clicks): Esc with nothing left to close quits
hub tabs                         the landed tabs as id, title and question (control-menu's hub rows)
hub tab log                      ask the running hub to switch tab (the next hub to start takes it when none runs)
hub tab projects agent-runtime   the same, opening one project's rows under its card (what tmux Prefix p sends); a name no card has opens All searched for it
hub --once                       print Home and Infra as plain text at $COLUMNS, then exit
hub --once --tab 'projects NAME' print one project's card over its open rows, what Enter shows (the tmux Prefix p preview)
hub --once --tab jobs            print one tab (`jobs` is Infra's jobs table); exit 1 when Prometheus did not answer
```

The tmux keys run `hub tab <name>; tmx goto hub hub:board`. The running hub listens on `~/.local/state/hub/tab.sock` and switches when the request arrives, with no file watch involved. When no hub is listening, the request is left in `~/.local/state/hub/tab`, `tmx goto` rebuilds the window, and the new hub starts on that tab. Only the first hub binds the socket; a second one still works by its keys.

## Tabs

A new tab or section follows `../docs/dashboards.md` (the dashboard standards, and the layout both hub surfaces are moving to).

| Tab | What it shows | Grafana (`o`) |
|---|---|---|
| 1 Home | `hub_core::home`, the reader agent-web's Home uses too. The two summary lines lead. NUMBERS: the queue (running, up next, held), done today, sessions by bucket, Claude spend in 24h. HEALTH: one chip per domain from `cc:domain_status`; all green is one line, otherwise only the chips that are not green. NEEDS YOU: pending asks, sessions waiting on a dialog, queue items waiting on you, a red nightly on main and what `cc:red_now` lists, one row per tmux session (an ask stands for its session and its queue item), newest first within each kind. RUNNING: the queue's running items with plan phase done/total, next phase and ETA (amber `late` once past it). Each list shows its first 8 rows (`hub_core::home::SHOWN`) and counts the rest on a `+N older` line. Under them, until the Infra tab takes them: CI busy/slots, POOLS, RUNNING jobs, the queue by pool, DOWN and the finished headline | `kb-command-center` |
| 2 Daily | `hub_core::focus`, the reader agent-web's Daily tab uses: the daily note's `## Focus` lanes item by item, word-wrapped, then Done, the rollup and the note's other sections counted and named. Read-only (`notes focus` and the editor write it). `[` / `]` step to the day before or after that has a note, `t` back to today. The head line ends `o outbox`: `o` shows the outbox in place of the note (`hub_core::outbox`: its waiting lines, then Handled today, what intake did with each line: filed, dup, planned, left or refused, with the row id and why), Enter opens it in `$EDITOR` in a new tmux window (the sweep files what is saved there 30s after the last save), and `o` or Esc goes back to the note. Read on entering, on `r` and on the 60s tick while shown. `2`, Tab, Shift-Tab or `hub --tab daily` (or the retired `focus`) open the note and `hub --tab outbox` the outbox | - |
| 3 Queue | `hub_core::queue`, the same reader as agent-web's Queue tab: `agent-queue list --json --state all` and `agent-queue stats --json`, never the store's files. The week's line (done by outcome, with a PR, the wait median and p90 over items that waited plus how many started at once, the time-to-PR median) and the sitting line (how many queued items could start now, the oldest with its slug and the median age, and how many are held by kind), both worded by `hub_core::queue::Stats` so agent-web prints the same text, then Waiting for you, Running, Up next and Done today, each item with its priority, project, mode, when it was queued, started or finished, its session, hold, or outcome and PR, and the task's first line. `j`/`k` pick an active item, `c` cancels it (`agent-queue cancel`, after `y`), `+`/`-` move its priority a step (`agent-queue bump`). Read on start (the Overview counts it), on entering, on `r`, after an action, and when an item file under `$AGENT_QUEUE_DIR` (default `~/.agent/queue`) is written. Below them the CANDIDATES fold (`hub_core::queue::candidates`, `fleet-dispatch suggest --json`), shut by default with its counts (`+ CANDIDATES (N, M auto)`): `f` opens it to the first 30 in rank order (rank, project, key, task, auto or man with the verdict and held, why) and `+N more`; `j`/`k` run on from the items into its rows, and `p` starts the selected one with `fleet-dispatch promote`, the Projects tab's `s`. It reads every board (seconds), so it is read in a worker on entering the tab, on `r` there and after an action, never on a queue file event. The page opens on one pipeline line (`hub_core::pipeline`, fleet-bench's `agent_chain_*` gauges through `prom.rs`: `pipeline  inbox 4  backlog 312  queued 3  running 5  waiting 2   o graph`, and a second `! bottleneck: waiting, age p90 9h (bound 4h)` line only when a step's `agent_chain_age_ratio` is above 1; the bound is age p90 over the ratio). With the gauges absent it reads `pipeline -`, never zeros; a failed read adds why. Read on entering, on `r` and on the 60s tick while shown. The section headings below it still count queued, running and waiting from agent-queue itself, the live source; the gauges add inbox and backlog | `kb-agents-overview` (Agents) |
| 4 Projects | `hub_core::projects`, the cards agent-web's Projects tab draws: one per lab project, in flight first, with a bar and `v0.0.1 36% (337 of 921 by size), 7d 103, 28d 239, ETA 69d` (the open version's rows weighted #size/s 1, m 3, l 8, unsized 1, from `notes projects --stats --json`; the ETA is open weight over the 28-day close rate, none when nothing closed), the goal, what is running with its plan phase, the queue counts and the dated status; then the active queue items no card claims. j/k pick, `P` steps the selected project's priority (normal, focus, high, low, shown as `prio focus` after the stage) through `notes projects --prio`, Enter opens the card's rows below it (Esc or Backspace goes back), and All opens every project's rows (`/` searches them, `l` steps the lane). The rows are `hub_core::tasks`, `notes board --json`, never the sheets, and wrap rather than clip. Under them, in at most a third of a window 18 lines or taller, the selected row in full: its id, project, lane, version, state, priority and size, the whole text, its tags, worker, since and filed dates and marker, and the sheet line a write lands on. Every project's open rows (human sheet, agent board, playtest checks) grouped by profile and project, each with its priority, lane, version (the game heading on a playtest check), state and text; Focus rows are not listed: All's head line counts them (`FOCUS  personal 3 open, on the Focus tab`). `/` searches, `l` steps the lane filter, and `a`, `s`, `d`/`D`, `x`/`X`, `m`, `e`, `+`/`-` and `o` add to the selected row's project and lane, start, finish (with a proof, or unverified with why), drop (with why, or the id of the row it duplicates; the row stays on the sheet, ticked, with the reason), move to another project or version, edit the text (tags stay), move a release sooner or later, `t`/`T` add or remove tags (`size/s`, `requested`; a new size replaces the old, a release is `m`'s), and open the sheet at the row in a new tmux window. A playtest check takes only add, done and drop. A write passes the row's raw line to `notes ptask --exact`, or for `s` to `fleet-dispatch promote`, which queues the row as an item that waits for the human to be away, so a row edited since the read matches nothing, nothing is written, and the status line shows notes' error. Read on entering, on `r`, after a write and on the 60s tick while shown; the vault has no watch here. `4`, Tab, Shift-Tab or `hub --tab projects` | - |
| 5 Sessions | One row per agent session: every live agent session and every `claude-acct park` ledger whose session has no live claude (`hub_core::session_actions::gather`), joined by target to its row in `~/.local/state/fleet/state.json` (sessions with no live claude here, such as another world's, are listed too). Rows rank by bucket (NEEDS, STALLED, DONE, LANDED, CHAT, WORKING, PARKED; a session with no state row is PARKED) with the stage, task, PR, CI, plan phases, ETA, idle, account, the pane you are on, the pending ask and the why. The ETA is the session's `fleet-bench forecast` p50 finish (red with "late" when it is), else fleet-state's. Enter opens the selected row's detail pane: every stage field, branch, next phase, what it said, its blockers, the account, plan file, queue item and offered actions, and its forecast timeline (the bar to the last slow finish and each phase's p50 and slow finish). A key arms an action and a confirm line says what it will do; nothing runs until `y`. Each action is the command that owns it: interrupt is Escape into the pane, park, unpark and move are `claude-acct`, stop types `/exit` then closes the window, cancel is `agent-queue cancel` (only for a session a queue item started), approve-plan presses the plan dialog's "Yes, auto-accept edits" digit (only while the pane shows that dialog; ASK then reads `plan ready`). A parked row offers only unpark; a row with no live or parked session here offers nothing. Above the table, the counts by bucket and the state file's age; below it, nightly reds and the open asks (the newest changes from `~/.agent/shepherd/watch.log`, which `fleet-state.timer` writes every minute, are Log's CHANGES fold). The forecast and the ranked sessions are folds on Log. Read on entering the tab, on `r`, after an action and on the 60s tick while it is shown | - |
| 6 Infra | Is the machinery healthy? `hub_core::infra` (Prometheus), sections in `hub_core::layout` order, `n`/`N` to step between them: HEALTH (the Home chips, then the numbers), RED NOW (`cc:red_now` first, then offline runners, stuck runs and exporter, rate or API trouble), MACHINES (one row per machine: where, busy, CPU now and over 6h, load per core, memory, temperature, slots per pool; machines with no runner show when named in `CC_HOSTS`), CI (one line `CI  running N  queued N  failed 24h N`, or one green line when all three are zero; then running, queued, finished in 24h per workflow, queues by pool and recent runs), JOBS (the first 8 rows; Enter, `/`, `s`, `f` or `h` opens the full table, Esc at its root comes back), CLOUD RUNNERS (`ci_governor_power_*`: state, today, override, why) and GOVERNOR (up, ok or blind, queue, one row per host). `hub --tab ci` or `hub tab 'infra machines'` opens it at a section. The jobs table: Every job `hub_core::jobs::collect` finds: agentctl runners (the run ledger), user timers (journald), Unity gates (the ledger plus running gates from `cc:host_local_gate`), CI and k8s from Prometheus. Queued, running and done with start, duration and result; Enter opens the log under the list. A k8s Job's log is its pods' lines in Loki, read through the API server's service proxy (`kubectl get --raw`, cluster `CC_KUBE_CONTEXT`, service `CC_LOKI_SERVICE`), so Loki needs no ingress and no token | `kb-ci-runners` |
| 7 Log | The day, then its history and the machinery's record, sections in `hub_core::layout` order. DAY: the day-log record (`~/.agent/daylog/<date>.json`, `day-log.timer` every 5 minutes): waiting on you, merged, still open, sessions bench, timeline, spend; `[`/`]` step a day, `t` back to today, `n`/`N` step the sections. HISTORY: `h` lists the recorded days (merges, repos, sessions, cost, areas); `j`/`k` and Enter open one, Esc goes back. Then six folds, each a head line with its count until its key opens it: ACTIONS `a` (`hub_core::actions`, the last 24h of what the machinery did, agent-web's Actions section), CHANGES `c` (the newest changes from `~/.agent/shepherd/watch.log`), RUNDOWNS `s` (the shepherd's kept rundowns in `~/.agent/shepherd/rundowns/`, stamp and title), JUDGES' VERDICTS `v` (the dispatch judge's newest verdicts and every answer verdict with why and what you did, `V` stepping all, answered, would answer, passed, wrong; `hub_core::fleet`), FORECAST `f` (`fleet-bench forecast`, `vs` and `flow`, `--json`: the all-done-by band, the drain, the queue, the burn-up and the frozen baseline against what happened since) and RANKED SESSIONS `w` (the week's sessions ranked by friction, `agentctl-session-outcomes worst`; `agentctl-session-outcomes card <id>` prints one). A fold is read when it opens, on `r` and on the 60s tick while it is open; each list stops at 50 rows (`hub_core::layout::FOLD_ROWS`) and counts the rest on a `+N older` line. The retired names `today`, `history`, `actions` and `forecast` land here | - |
| 8 Fleet | The machinery that runs the agents (the sessions are on Sessions, key 5): `hub_core::fleet::collect`, the same reader as agent-web's Fleet tab: the Claude accounts (claude-acct's textfile in Prometheus), one row per agentctl runner in `~/.config/agentctl/agents/*.conf` (last outcome and when, runs and failures in 24h from the run ledger, the last "why" from `activity.log`, the next timer fire, dollars in 24h by the `agentctl_runner` OTel label; `d` puts each runner's registry under its row: role and what it takes away, model, prompt and sha, trigger, 24h calls, errors, cost, tokens and p95 from `calls.jsonl`, the newest call's Langfuse trace, and for a judge its per-rule `judge-eval` table; `t` lists them in hub-core's Tonight order, as agent-web's Tonight button), the dispatch judge (`~/.agent/dispatch/verdicts.jsonl`, counts by verdict for 24h and 7d, starts and reaps from `log.md`) and the answer judge (agree, disagree, deferred, pending from the asks). The verdict lists are Log's VERDICTS fold (`7`, then `v`). Read on entering, on `r`, on an agentctl ledger write and on the 60s tick while it is shown | - |

Prometheus pages re-read every 60s (`PROM_REFRESH`; Prometheus has no push). Everything else re-reads when its file is written (inotify; an open is not a write): Infra's jobs on the agentctl state dir and the Unity ledger (CI and k8s on the 60s tick), Log's CHANGES on the fleet state and `watch.log`, its RUNDOWNS on `~/.agent/shepherd/rundowns/`, Log's day and history on `~/.agent/daylog/`, Queue and Home's running list and numbers on any `.md` under the queue dir. Log's FORECAST, ACTIONS and RANKED SESSIONS folds have no file to watch: they read when opened, on `r`, and on the 60s tick while open. Fleet's accounts, runners and judges read the same way, and also when the agentctl ledger is written; the dispatch and ask files have no watch here, so they show on the next tick. When a watch cannot be set (inotify full), the tab bar says "no file watch" and the 60s tick reads those files instead.

## Keys

| Key | Does |
|---|---|
| `1`-`8`, Tab, Shift-Tab | Switch tab, in `hub_core::layout` order: 1 Home, 2 Daily, 3 Queue, 4 Projects, 5 Sessions, 6 Infra, 7 Log, 8 Fleet. Tab cycles the eight tabs |
| Esc | With `--popup`, once nothing is left to close (a pane, filter, prompt, confirm or the jobs table), quit; without it Esc never quits |
| `r` | Re-read now |
| `o` | Open this tab's Grafana dashboard (in the jobs table: the selected row's URL) |
| `j`/`k`, PgUp/PgDn, space, `g`/`G` | Scroll a page; in the jobs table, move the selection |
| `n` / `N` | Infra: the next / previous section |
| Enter, Esc | Infra: open the jobs table; at the table's root (no log, history, search or filter), back to the summary |
| `s` / `f` | Jobs table: cycle the source / state filter |
| `/` | Jobs table: search name, detail, result and source (Enter applies, Esc cancels) |
| `h` | Jobs table: every run of the selected job, unfolded (again to go back) |
| Enter | Jobs table: open the selected row's log (follows the tail) |
| `J`/`K`, PgUp/PgDn | Jobs table, log open: scroll the log |
| Esc | Jobs table: close the log, then history, then clear the filters |
| `[` / `]`, `t` | Log: the day before / after, back to today. Daily: the day before / after that has a note, back to today |
| `o`, Esc, Enter | Daily: show the outbox, `o` or Esc back to the note; on the outbox, Enter opens it in `$EDITOR` in a new tmux window |
| `d` | Fleet: show or hide each runner's registry lines under its row |
| `t` | Fleet: Workers in Tonight order (always-on, then each timer start until 07:00, each call under its caller, other timers as a count), or back to the default |
| `/`, `f`, `l`, `s`, Esc | Fleet: search name, description and why (Enter keeps it, Esc clears it); step the state (all, failed 24h, running, idle, off), the lane, the sort (runs, failed, cost, last, biggest first); Esc clears them all. A sort does not apply to Tonight order |
| `n` / `N` | Log: the next / previous section |
| `h`, `j`/`k`, Enter, Esc | Log: list the recorded days, pick one, open it, close the list |
| `a` `c` `s` `v` `f` `w` | Log: open or fold Actions, Changes, Rundowns, Judges' verdicts, Forecast, Ranked sessions (an open fold is read and scrolled to) |
| `j`/`k`, Enter, Esc | Sessions: pick a session (PgUp/PgDn, space and `g`/`G` scroll the page), open or close its detail pane |
| `i` `p` `u` `m` `x` `c` `a` | Sessions: interrupt, park, unpark, move, stop, cancel, approve the plan of the selected session; each asks first |
| `y`/Enter, `n`/Esc, Left/Right | Sessions, confirm armed: run it, drop it, pick the account a move goes to |
| `j`/`k`, `c`, `+`/`-` | Queue: pick an active item, cancel it (asks first), raise or lower its priority |
| `f`, `p` | Queue: open or fold the Candidates, promote the selected candidate (`fleet-dispatch promote`) |
| `y`/Enter, `n`/Esc | Queue, cancel armed: run it, drop it |
| `j`/`k`, PgUp/PgDn, space, `g`/`G` | Board: move the selection (the page follows it) |
| `/`, `l`, Esc | Board: search project and text (Enter applies, Esc clears), step the lane filter, clear both |
| `a` | Board: add a row to the selected row's project and lane; `#urgent` or `#low` in the text sets its priority |
| `s`, `d`, `D`, `x`, `X` | Board: queue the selected row, mark it done with a proof (pr:N, a URL), done unverified with why, drop it with why, drop it as a duplicate of an id; not on a Focus row |
| `m`, `e`, `+`, `-` | Board: move the row (a project, a version `vX.Y.Z`, or both, space-separated), edit its text (tags kept), one release sooner, one release later; not on a playtest check or a Focus row |
| `o` | Board: open the row's sheet at its line in `$EDITOR` (one word, else nvim) in a new tmux window |
| `q`, Ctrl-C | Quit |

## Environment

| Variable | Meaning |
|---|---|
| `CC_PROM_URL`, `CC_GRAFANA_URL`, `CC_HOSTS` | Read from `~/.config/command-center/env` (private overlay) unless set. `CC_GRAFANA_URL` is a dashboard link; the board links from its base. `CC_HOSTS` (default `workstation`) lists machines to show with no runner |
| `NO_COLOR` | Any non-empty value: no colour; bold and the reversed selection stay |
| `COLUMNS` | Width for `--once` (else the terminal's, else 80) |
| `AGENT_QUEUE_DIR` | The queue dir to watch, as agent-queue reads it (default `~/.agent/queue`); the items themselves always come from `agent-queue` on PATH |

## Tests

`cargo test` here: the board sections against a fixture Prometheus answer (ported from the old `command_center.bats`), the Jobs table, filters and log cleaning, the Sessions table and its detail pane, Log's day, history and folds from fixture records (`logtab.rs`), the forecast band and each session's timeline from real `fleet-bench` answers in `tests/fixtures/`, the Fleet machinery from a fixture `hub_core::fleet::Fleet` (`fleettab.rs`), the Queue page, its keys and the Overview's counts from a fixture `hub_core::queue::Queue` (`queuetab.rs`), the Board page, its filters and the argv of each write from a fixture `hub_core::tasks::Feed` (`tasktab.rs`), `hub tab` over the socket and the request file (`tabreq.rs`), and whole-screen `TestBackend` renders driven by keys. The session controls and the queue's cancel run against a fixture and a fake runner (`controls.rs`, `queuetab.rs`, `app.rs`), so no test reaches tmux, claude-acct, agent-queue or notes. `tests/rust.sh` runs them in CI. Never drive the TUI on the live tmux server; use an isolated one (`tmux -L <name>`), or the container tier.

## Troubleshooting

| Symptom | Cause and fix |
|---|---|
| No CI job ever shows as running in the jobs table | The exporter calls a busy runner `github_runner_state{state="running"}`, and hub-core `jobs/remote.rs` asks for `running` (fixed 2026-11-03) |
| Running Unity gates missing from the jobs table, only finished ones | The ledger only gets a row when a gate ends; running gates come from `cc:host_local_gate` (fleet-assess textfile), merged in `jobs::collect` |
| Columns after an emoji row shift by one | A wide character takes two columns; `fit.rs` measures with `unicode-width`, never `chars().count()` |
| `o` opens a 404 like `.../d/kb-ci-runners/d/...` | `CC_GRAFANA_URL` is cut to its base in `hub_core::infra::gather`; an older binary does not. Rebuild |
| "QUERY FAILED" and no machines | Prometheus did not answer or `cc:overall_status` is missing. The board never shows the last numbers after a failed read; check `CC_PROM_URL` and the recording rules in home-config `apps/monitoring/prometheus-rules-command-center.yaml` |
| "unread: ..." under the jobs table status line | That source failed to read (named in the line); the other sources still show |
| "no log kept for this row" | That source keeps no log (Unity gates) |
| "CC_KUBE_CONTEXT is not set" or "CC_LOKI_SERVICE is not set" on a k8s log | The cluster and the Loki service come from `~/.config/command-center/env` (private repo): `CC_KUBE_CONTEXT=home-k3s`, `CC_LOKI_SERVICE=monitoring/loki:3100` |
| A k8s log says "kubectl: ..." | The API server refused or timed out (10s guard). `kubectl --context home-k3s get --raw /api/v1/namespaces/monitoring/services/loki:3100/proxy/ready` shows whether Loki answers |
| "Loki has no lines from this Job's pods" | The pod wrote nothing, or Alloy (home-config `apps/alloy`) did not ship it. Loki keeps a year |
| Log's FORECAST fold says "No forecast: ... exit 2, usage" | The `fleet-bench` on PATH has no `forecast`, `vs` or `flow` verb (exit 2 is its usage). Pull the checkout `~/.local/bin/fleet-bench` links to |
| Log's FORECAST fold says "no baseline yet" | `fleet-bench vs` found no frozen forecast: `fleet-bench forecast --baseline <label>` freezes one |
| Sessions says no fleet state, or its changes stop moving | `fleet-state.timer` is not running: `systemctl --user enable --now fleet-state.timer`. The timer builds the log whether or not the tab is open |
| Log's day is a day behind or empty | `day-log.timer` is not running: `systemctl --user enable --now day-log.timer`; `day-log snapshot` writes one record by hand |
| Prefix i lands on the wrong tab | A hub older than the tab socket ignores the request. Rebuild, then `tmux kill-window -t hub:board` and press the key again |
| "hub tab cannot reach this hub (...)" in the tab bar | `tab.sock` would not bind; the reason is in the brackets. A socket path is limited to 108 bytes, so a long `XDG_STATE_HOME` cannot hold one |
| "no file watch (inotify full)" in the tab bar | Every inotify watch is taken. `grep -c '^inotify' /proc/[0-9]*/fdinfo/* 2>/dev/null \| awk -F'[/:]' '{n[$3]+=$NF} END{for(p in n) if(n[p]) print n[p], p}' \| sort -rn \| head -3` prints watches and pid, biggest first; an open Unity Editor's `Unity.ILPP.Runner` can hold nearly all of `fs.inotify.max_user_watches`. Closing it or raising the limit is the human's call. Until then the board re-reads its files every 60s, and agent-web will not start, so do not restart it |
| hub holds 100%+ CPU and a `journalctl --user ... MESSAGE_ID=...` child respawns non-stop | notify asks inotify for opens too, and each jobs read opens the files it watches, so every read woke the next. `is_write` in `app.rs` drops everything but create, modify and remove (fixed 2026-11-03). Rebuild and restart the hub |
| Status chips unreadable (yellow on yellow) | Chips are black text on the status colour, so a theme that maps red and green to light shades still reads; the word (OK, WARN, RED, NODATA) carries the state |
| Queue or Home shows a yellow `agent-queue ...` line | `agent-queue` failed or is not on PATH; the line is its error. The page shows what still read (items without the week line, or the reverse). Run the same `agent-queue list --json --state all` by hand to see it |
| Queue does not move when an item changes | The queue dir did not exist when hub started, so it has no watch on it. `r` reads it; restart hub to watch it |
